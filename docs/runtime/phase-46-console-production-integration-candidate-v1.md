# Phase 46 - Console Production Integration Candidate v1

## Purpose

Phase 46 adds a Console-side production integration candidate flow for accepted controlled-apply review lineage. It prepares an isolated integration candidate workspace and writes evidence for later human review.

This phase creates an integration candidate only. It does not deploy, push, merge to main, create a PR, auto-commit, mutate the main working tree, or bypass controlled-apply review evidence.

## Endpoint

`POST /api/engineer-console/prototype-loop/integration-candidate`

The route uses the existing Console mutation authorization pattern and returns `Cache-Control: no-store`.

## Input / Output Contract

The request accepts accepted controlled-apply review lineage:

- Controlled apply review decision id.
- Controlled apply id, evidence path, and isolated workspace path.
- Apply approval, apply proposal, implementation plan, implementation request, and prototype approval ids.
- Task/run/prototype evidence lineage, with optional revision lineage.
- Plan and proposal paths.
- `controlled_apply_status: controlled_apply_completed`.
- `checks_passed: true`.
- `review_required: true`.
- `integration_allowed: false`.
- `production_integration_intent_recorded: true`.
- Merge/deploy/PR/production mutation flags set to false.
- `requested_integration_intent: prepare_integration_candidate_in_isolated_workspace`.
- Non-contradictory safety constraints.

The response includes:

- `integration_candidate_status`: `integration_candidate_recorded`, `blocked`, or `failed`.
- Generated `integration_candidate_id`.
- Isolated workspace path and evidence path.
- Full upstream lineage.
- Files changed inside the isolated workspace.
- Check results and `checks_passed`.
- Rollback plan.
- `review_required: true`.
- `final_integration_approval_required: true`.
- `main_tree_mutated: false`.
- Merge/deploy/push/PR/commit/production mutation flags set to false.
- Vera-facing summary.

## Validation Rules

The service blocks when required lineage ids or paths are missing, controlled apply status is blocked or failed, checks did not pass, review is not required, production integration intent was not recorded, integration was already allowed, merge/deploy/PR or production mutation flags are true, requested intent is wrong, safety constraints are missing or contradictory, the user note asks to merge/deploy/push/PR/commit/direct-main mutate, or the request attempts to bypass evidence, controlled-apply review, or final approval.

## Isolated Workspace Behavior

The service creates generated workspaces under:

`.integration-candidates/<integration-candidate-id>/`

The id is generated by Console, normalized as a safe path segment, and guarded so it cannot escape `.integration-candidates/`. Phase 46 uses a safe folder workspace rather than a git worktree. `.integration-candidates/` is gitignored.

The service materializes deterministic candidate files and metadata inside the isolated workspace only:

- `integration-candidate-manifest.json`
- `intended-production-targets.json`
- `candidate-files/word-count-cli.mjs`
- `candidate-files/word-count-cli.test.mjs`
- `candidate-files/sample.txt`

Intended production target paths are metadata only. No candidate file is copied into the production source tree.

## Evidence Artifact

Evidence is written to:

`evidence/prototype-integration-candidates/<integration-candidate-id>.json`

The evidence includes the integration candidate id, timestamp, status, blocked/failure reason, workspace path, full lineage, files changed in the isolated workspace, intended production target metadata, checks, rollback plan, final-review flags, explicit non-actions, workspace manifest, and next expected phase.

## Checks

Phase 46 runs scoped checks in the isolated workspace:

- `node --check candidate-files/word-count-cli.mjs`
- `node --test candidate-files/word-count-cli.test.mjs`

If checks fail, the result is `failed`, evidence is still written, and production remains untouched.

## No-Main-Tree-Mutation Boundary

Phase 46 does not write to the main working tree, apply patches to production files, copy prototype files into production, commit, push, create PRs, merge, or deploy. It does not call Vera approval routes, run another revision, add AirLLM, add Super escalation, route models/providers, create automations, or send email.

## Known Limitations

- The candidate content is deterministic and narrow for Phase 46.
- Intended production targets are metadata only.
- No branch, PR, commit, deployment, or production integration executor is created.
- Final production integration approval/execution remains a future phase.
